## What's new in v1.19.0
Updates that need a newer Home Assistant than you are running are now identified, hidden by default, and can't be installed by accident.

### Added
- **Incompatible updates are held back.** The Update Action Tracker card reads the minimum Home Assistant version each component declares and compares it with yours. Anything that needs a newer Home Assistant is left out of the list, and the header shows how many — so the count beside the title is never quietly short.
- **"Show incompatible"** reveals them, marked and dimmed, with the version they need and the version you have. They still cannot be installed from the card: there is no Update button on those rows at all, just Skip and a line saying what would unblock them.
- **Every listed update states its requirement** — ● met, ◐ needs a newer Home Assistant, or ○ requirement unknown — in shapes and words, so nothing relies on colour.
- **Components that declare nothing** stay in the list and are labelled "Requirement unknown". They are never called compatible, they are left out of bulk installs, and installing one needs a tick on that row first. The tick is forgotten as soon as you close the row.
- **The bulk button names its own scope**: "Update all (5)", "Update selected (3)" or "Update 3 of 5" — and the confirmation dialog quotes the same number it will actually install.
- **Two new attributes on `sensor.hacs_updates`** — `updates_blocked` and `updates_unknown_requirement` — so an automation can act on "two updates need a newer Home Assistant" without reading the whole list.

### Fixed
- `custom_component_monitor.update_and_action` now refuses an update whose declared minimum isn't met, with an error naming both versions, instead of installing it and leaving you to roll it back by hand.
- `custom_component_monitor.update_all` skips those components and names them in the log, rather than installing some and failing on others partway through.
- "Update all" previously told the service "install everything you can find". It now always sends the explicit list of what the card was showing, so a hidden update can't be installed by a button that wasn't offering it.

### Upgrade notes
- Restart Home Assistant after updating, then **hard-refresh your dashboard** to load the updated card (all four cards are bumped to 1.19.0).
- The requirement comes from the component's own HACS manifest. Most components don't declare one, so expect a lot of "Requirement unknown" — that is honest, not a fault. An unknown requirement is not a promise that the update works.
- Home Assistant's own update entity (its more-info dialog, Developer Tools, or an automation calling `update.install`) is not this integration's service and can't be intercepted. The protection here covers this card and this integration's two install services.
- No dashboard changes are needed. Sensor IDs, card types, service names and to-do history are unchanged.
