## What's new in v1.22.0
Two reported bugs. One wasted real AI time and could keep the model busy for hours over and over again; the other just made a mess of the log after every restart.

### Fixed
- **Dismissing a new item no longer makes the AI re-do work it had already finished** ([#77](https://github.com/loryanstrant/HA-CustomComponentMonitor/issues/77)). Dismiss used to trigger a full rescan of everything HACS knows about, which replaced the list the AI run was working through. Every answer the model had already given for the *other* items was then thrown away — not just unused, but never saved either — so the component decided the work was still outstanding and asked the model for all of it again. On a store with a few hundred new items that is hours of re-asking, and dismissing a few more items while it runs restarts it each time.
- **An AI answer is now saved the moment it arrives**, before anything is shown and before anything else can get in the way. That holds even for an item you dismissed a second earlier: an answer about a repository stays true whatever you did to your review queue while the model was thinking, and the saved answer is what Restore by category matches against later.
- **Dismissing is now instant and local.** The item disappears from the card and the dismissed count goes up, with no rescan behind it. Restore still rescans — it has to, because it brings rows back.
- **No more error lines in the log after a restart for something that is just startup timing** ([#76](https://github.com/loryanstrant/HA-CustomComponentMonitor/issues/76)). Every Home Assistant restart races HACS's own startup, and the first scan or two losing that race is the system working as designed. v1.21.0 wrote it as an error, twice over — once from this component and once from Home Assistant itself. It is now written once, as information.
- **A genuinely stuck HACS is still reported loudly.** HACS can report "starting" for the whole time Home Assistant is up, which is a real fault and not startup timing. If the condition lasts more than 10 minutes it becomes an error in the log, once.

### Upgrade notes
- Restart Home Assistant after updating, then **hard-refresh your dashboard** to load the updated cards (all four are bumped to 1.22.0).
- If the AI has been churning through the same new items repeatedly, this stops after the update. Anything it already answered correctly is kept; nothing is re-asked.
- The `categorise_new_items` service still reports a `skipped` count, now always 0. The number it used to carry was the bug — items whose answer had been thrown away. It is kept so existing automations reading the response don't break.
- No dashboard changes are needed. Sensor IDs, card types, service names and to-do history are unchanged.

### Not fixed here, because it isn't ours
The `Event is not JSON serializable` warning quoted in [#77](https://github.com/loryanstrant/HA-CustomComponentMonitor/issues/77) does not come from this component — Custom Component Monitor fires no events at all. It comes from the local OpenAI LLM integration doing the categorising ([skye-harris/hass_local_openai_llm](https://github.com/skye-harris/hass_local_openai_llm)), which fires a completion event carrying a raw object from the OpenAI client library that Home Assistant's recorder cannot store. It is harmless and worth reporting to that integration's author.
