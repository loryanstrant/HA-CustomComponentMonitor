## What's new in v1.21.0
The "will this run on my Home Assistant?" check on pending updates was reading the wrong release. It's fixed, and for one real update in this house it was wrong in a way you'd only notice by reading the small print.

### Fixed
- **A pending update's compatibility check could be checking the version you already have, not the one being offered.** HACS keeps exactly one `hacs.json` snapshot per repository, and nothing records which release that snapshot describes. When a new release appeared, the check kept reading the old snapshot's `homeassistant` minimum rather than the new release's — so the card could tell you an update was fine when the update itself needed a newer Home Assistant than you have.
- **Worked example:** on this house's own production instance, six of seven pending updates happened to need the same Home Assistant version whether you looked at the installed or the offered release, so the bug was invisible on them. The seventh — **Microsoft 365 - Calendar v1.14.0** — did not: the card said "Needs Home Assistant 2025.6.0 — you have it" (the *installed* v1.13.0's requirement), while the release notes rendered a few lines below in the same card said the new version needs 2026.11.0. The header read "7 updates / 2 incompatible"; the true count was 3.
- **The check now re-reads the requirement from the update actually being offered**, fetched from that release's own `hacs.json` rather than the cached snapshot. A successful read is kept for the life of the running Home Assistant (a release's contents don't change after it ships), so this costs one small read per newly-offered update and nothing on top of that afterwards.
- **A read that fails no longer keeps the old answer.** If the offered version's manifest can't be fetched this scan, the row reports **Requirement couldn't be checked** rather than repeating whatever was cached before — and a requirement already known to be **blocked** still wins over an unknown, so a guess is never upgraded to a green tick. The next hourly scan tries again.

### Upgrade notes
- Restart Home Assistant after updating, then **hard-refresh your dashboard** to load the updated card (all four cards are bumped to 1.21.0).
- **Any ● met or ◐ blocked verdict from v1.19.0 or v1.20.0 could have been wrong**, in either direction: the stale snapshot was simply the *previous* release's requirement, so it read as too lenient when a release raised its minimum (the Microsoft 365 Calendar case above) and too strict if a release ever lowered one. The dangerous half is the lenient one. If you installed something on the strength of a ● met row in that window, it's worth checking that update's own release notes for its real Home Assistant requirement.
- HACS's own install gate has this exact same blind spot — it compares against its stored manifest regardless of which release is being installed — and the upstream fix for it has never shipped in a release. HACS will not reliably stop you installing an update whose requirement it has mis-read; this card is the protection. Home Assistant 2026.11's built-in Marketplace checks correctly.
- No dashboard changes are needed. Sensor IDs, card types, service names and to-do history are unchanged.
